实习第一个月总结：从校园到企业的AIGC实战之旅

本文章由AI阅读commit记录生成，效果感觉一般，意淫了不少我的想法XD

2026年6月25日到7月25日，我在厦门寻雷科技完成了第一个月的实习。这一个月里，我深度参与了一个电商AIGC平台的开发，同时接触了前端（React/Taro）和后端（Go/GoZero），算是真正从”写demo”进入了”做产品”的阶段。

项目概览

实习所在的项目是一个跨境电商AIGC内容生产平台，核心是用AI帮助商家生成营销视频、管理素材。技术栈方面：

  • 后端：Go + GoZero 微服务架构，包含 gateway / platform / aggregation / material 等多个服务
  • 前端：Monorepo 架构（pnpm workspace），PC端用 React + Vite，H5用 Taro，App端用 Capacitor
  • AI能力：接入寻雷Bernini、DeepSeek等多个AI服务商

第一个月我提交了大约 40+ 个 commit，覆盖前端和后端，主要集中在以下几个方向。

一、AIGC视频生成：最核心的业务线

1.1 寻雷Bernini对接

这是我最先接触、也是贯穿整个月的核心工作。寻雷Bernini是一个AI视频生成服务，我们需要把它接入到平台中来。

后端方面：

  • 对接了 Bernini 的文生视频/图生视频独立接口，处理了各种上游的异常情况（progress字段类型不一致、超长错误消息截断等）
  • 实现了上游无鉴权防御体系：包括按模型维度隔离的限流策略（窗口缩短到5秒）、并发控制、幂等性保证、计费顺序校验 —— 这套东西让我第一次真正理解了”防御性编程”在真实业务中的意义
  • 视频下载可靠性增强：OSS跨桶防护、私有OSS 403问题修复、永久失败检测
  • 孤儿任务清理机制：寻雷AI进行中的任务如果长时间无响应，自动标记并清理

前端方面：

  • 实现了未完成视频的静默轮询机制，修复了”上游已完成但前端一直显示processing”的经典bug
  • 视频列表的渲染优化、refreshOnShow自动刷新
  • 海南Bernini前端临时隐藏1080p和>18s的选项（因为上游暂时不支持）

1.2 视频草稿流式预览 (SSE)

这是我觉得最有意思的一个功能：让用户在创建视频草稿时，能够实时看到分镜故事板的生成进度。

  • 后端实现了 CreateVideoDraftStream 流式接口，基于 DeepSeek 的 SSE 推送
  • 支持带签名URL的参考文件、Vision图片协议
  • 前端对接了SSE流式响应，做了状态轮询和错误处理
  • 整个流程从”点一下等结果”变成了”看着AI一步步生成”，体验提升很大

1.3 定价与计费体系

AIGC功能涉及到真金白银的计费，这一个月的改动包括：

  • 更新AIGC定价体系，支持按秒时长计价规则（注意是向下取整，不是向上取整，踩过坑）
  • 视频翻译的积分冻结与结算流程
  • 视频克隆的积分预估显示

二、安全加固：从”能用”到”安全”

实习第二周开始，导师安排我做了一轮安全审计和加固。这是我第一次系统性地思考Web安全问题，学到了非常多。

2.1 后端安全

  • 寻雷AI上游无鉴权防御：限流、并发控制、幂等性（上面说过了）
  • Mock支付HTTP入口禁用：线上绝对不能留这种调试接口
  • 脚本白名单清理：删除了僵尸接口和临时验证码
  • API防自动化接口分级草案：为后续的接口安全治理搭了框架
  • 第一批&第二批安全问题修复：包括DB字段类型调整（VARCHAR→TEXT防止截断）、敏感信息泄露等

2.2 前端安全

  • XSS防护：输出编码、输入校验
  • 开放重定向修复：所有跳转链接加白名单校验
  • API Key配置加固：确保不在前端代码中硬编码敏感信息

最大的感受：安全不是一次性的任务，而是需要持续关注的工程实践。很多时候漏洞不是因为”没想到”，而是因为”太着急上线忘了做”。

三、工程化与文档沉淀

导师很强调”代码要能交接”，所以这个月我花了不少时间在文档和工程规范上：

  • 编写了前后端部署方案文档，让新人能快速搭起环境
  • 沉淀了Commit规范 + AIGC任务排障知识到AGENTS.md
  • 做了前后端代码质量审计及修复方案
  • 重组了安全/代码审查与运维经验文档
  • 补齐了多个client包的type alias，让RPC类型可以透传
  • 调整了 project 结构，删除废弃的 userextrasetting 包

这些工作看起来”不写代码”，但实际对团队效率的提升很大。我自己后面排障的时候也经常回看之前写的文档。

四、基础设施：文件处理与上传

4.1 OSS 文件处理

电商平台少不了文件上传下载，这个月涉及了不少OSS相关的工作：

  • 视频封面改用缓存jpg + OSS实时转WebP：减少存储成本的同时提升加载速度
  • OSS2 新增 GetObjectPublicURL 公共直链构造
  • 参考图与封面上游URL区分处理（r2v场景下两者的OSS路径不同）
  • 私有OSS 403问题的排查和修复

4.2 上传功能

  • 前端：修复了上传失败后重试不发新请求的Bug（这个问题很坑，之前失败后点重试用的是缓存的旧请求，一直报同样的错）
  • getUploadUrl 改为 mutation 方式调用，避免缓存问题

五、知识库与RAG功能

平台有一个”轻量RAG”功能，帮商家基于知识库生成内容。这个月做了一些增强：

  • 知识库文档列表会话缓存（避免每次切换tab都重新请求）
  • 轻量RAG开关与商家画像注入（根据商家特征定制生成内容）
  • 前端 fetchKnowledgeDocuments 提取 items 局部变量，代码更清晰

六、踩过的坑 & 学到的经验

  1. 类型不一致是魔鬼：上游接口返回的 progress 有时是 int 有时是 object，兼容处理很烦但必须做
  2. 限流要按维度隔离：全局限流会让正常用户和异常用户一起被挡，必须按模型/用户维度分别限流
  3. 字段长度要留余地：VARCHAR(255) 不够用，错误消息经常超长，后来改成了 TEXT
  4. 发布前多做预校验：与其等上游报错再处理，不如在本地就做好参数校验，提前拦截
  5. 好文档能救命：这个月排了好几次障，都是靠之前写的文档快速定位问题
  6. 安全是持续的事：不是做完一轮审计就完事了，每次加新功能都要考虑安全

写在最后

第一个月的实习强度确实不小，但收获也很大。从最开始的”看代码不知道从哪下手”，到现在能独立排查问题、写方案、提PR，感觉自己在慢慢变成一个真正的工程师。

下个月的目标：

  • 继续深入AIGC视频生成链路，争取把整个pipeline吃透
  • 多一些性能优化和监控方面的工作
  • 把Go的并发编程和微服务治理再提升一个台阶

加油吧。
